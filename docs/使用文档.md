## 1. 这是什么

一个给**地图作者**与**短片作者**用的视觉特效工具包。所有特效都是**客户端渲染**（不改存档结构、不加实体），指令在**服务端注册**，所以**做地图时服务端和客户端都要装**。

包含：

| 分类 | 内容 | 入口 |
|---|---|---|
| 镜头特效 | 视角抖动、白屏震撼弹 | 指令 |
| 文字特效 | 字幕、清空字幕 | 指令 |
| 倒计时 | 6 种样式，可红石检测 | 指令 |
| 通知 | 右下角通知卡片 + 全屏历史 | 指令 / `P` 键 |
| 聊天栏 | 弹起 / 滑出 / 滑入动画 | 自动生效 |
| 线圈道具 | 加速 / 重力 / 治愈 | 创造物品栏 |
| 喷气背包 | 飞行 + 热量系统 | 创造物品栏 |
| 红石延时器 | 信号整体延后 | 创造物品栏 |
| DFC 显示器 | 三块大屏 + 遥控器 | 创造物品栏 |

### 安装

1. 装好 Forge 1.12.2-14.23.5.2864；
2. 把 `jiezhi-1.12.2-dfcmaptools-3.4.jar` 丢进 `.minecraft/mods/`（**服务端也要放**）；
3. 启动，日志里看到 `jiezhi` 大字 LOGO 与 `JiezhiMod v3.4 is loading.` 即加载成功；
4. 进世界输入 `/shake 40` 自我验证。

### 谁可以执行

| 执行者 | 可用范围 |
|---|---|
| OP 玩家 | 全部指令 |

## 3. 特效指令详解

### 3.1 `/shake` 视角抖动

```
/shake [@target] <ticks> [intensity]
```

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| `ticks` | 1 ~ 2000 | 必填 | 抖动持续时长，20 ticks = 1 秒 |
| `intensity` | 0 ~ 90（度） | **4.0** | 峰值摆幅，超过 15 度已经很晕 |

**行为**：3 tick 起振冲到峰值 → 主震指数衰减到 28% 平台 → 后半段 `(1-r)^1.5` 余震缓慢收尾。噪声推进速度随强度变化（强震晃得快、余震晃得慢），不是均匀抽搐。抖动采用**相对基准视角的瞬时偏移**，结束后视角精确回到原位，不会留下偏移。

```
/shake 40              # 抖 2 秒，默认强度 4 度
/shake 30 12           # 抖 1.5 秒，强度 12 度（近距离爆炸）
/shake @a 60 8         # 全场抖 3 秒
```

### 3.2 `/white` 白屏震撼弹

```
/white [@target] <ticks> [alpha]
```

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| `ticks` | 1 ~ 2000 | 必填 | 主闪时长 |
| `alpha` | 0.0 ~ 1.0 | **1.0** | 峰值不透明度 |

**行为**（整屏纯白 + 三段式曝光曲线）：

1. 渲染就是**一整块纯白矩形**铺满屏幕，没有暗角、没有光晕、没有放射光芒，`alpha=1.0` 时完全不透明，画面被彻底盖住。
2. 曝光曲线：3 tick 爆闪冲峰 → 主段快速衰减 → **自动追加 1~4.5 秒余像**（全屏白色像视网膜残留一样慢慢变透），此阶段自动关闭模糊。
3. 强闪阶段叠加内置模糊 `shaders/post/blur.json`；加载失败或被其他模组占用时**静默降级**（只白不模糊），不会崩；离开世界时强制恢复画面。

```
/white 30              # 主闪 1.5 秒，满不透明
/white 25 0.8          # 主闪 1.25 秒，80% 强度（适合连发闪光弹）
/white @a[team=red] 40 # 只对红队队员闪
```

### 3.3 `/sub` 字幕

```
/sub [@target] [ticks] <text...>
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `ticks` | **80**（4 秒） | 只有首参数是纯数字时才被当作时长，否则整段都是文本 |
| `text` | — | 支持 `\n` 换行、`\u00a7` 颜色码、双引号分组 |

有 10 tick 的底部滑入 + 淡入动画，末尾 10 tick 淡出。多条字幕依次向上堆叠。

```
/sub @a 100 任务开始
/sub @a "\u00a7c警告\u00a7r：反应堆过载"
/sub @a 120 第一行\n第二行
/sub 60 大家好          # 省略目标 = 自己
```

### 3.4 `/subtitleclear` 清空字幕

```
/subtitleclear [@target]
```

立刻清空该目标的字幕队列（不等自然过期）。切场景、转场时用。

## 4. 倒计时

服务端权威计时，客户端每 tick 平滑递减，**服务端每秒广播一次全量纠正**，新玩家进服自动同步。显示在屏幕上方中央，多条自上而下排列，行距 30 px。

### 4.1 `/countdown_add`

```
/countdown_add <样式1-6> <名称> <秒数> [r] [g] [b]
```

| 参数 | 范围 | 默认 |
|---|---|---|
| 样式 | 1 ~ 6 | — |
| 名称 | 任意字符串（同名会**覆盖**） | — |
| 秒数 | 1 ~ 999999 | — |
| r g b | 0 ~ 255（**三个必须一起给**，否则忽略） | 255 255 255 |

回显示例：`Added countdown 'wave1': style=6 (precise + progress bar), 01:30, rgb(130,255,150)`
样式 2 固定红色，会忽略 rgb。

### 4.2 六种样式

| 样式 | 外观 | 特点 |
|---|---|---|
| **1** | `01:30` + 下方横线 | 最朴素，rgb 上色 |
| **2** | `\\\01:30///` | 固定红，斜杠从外向内逐个高亮（暗→亮→暗往返） |
| **3** | `┌01:30┐` | rgb 描边框住时间 |
| **4** | `01:30.4` | 十分之一秒；**10 秒内小数位转黄、3 秒转红** |
| **5** | `!01:30.4!` | 感叹号包裹；**5 秒内感叹号脉冲闪烁、3 秒整体转红** |
| **6** | `01:30.4` + 进度条 | 条随剩余时间收缩；rgb → 黄（10 秒内）→ 红（3 秒内呼吸闪烁） |

共同规则：

- 时间**向上取整**：3 秒倒计时立刻显示 `03`，最后 1 tick 仍显示 `00:01`（不会提前跳 0）。
- 样式 4/5/6 用渲染帧间插值，十分位连续走动而不是每 tick 硬跳。
- 最后 **5 秒**整体做脉冲放大心跳提醒。
- **归零后不自动删除**，屏幕保留压暗的 `00:00`，需手动 `/countdown_remove`；这样 `/countdown_test 名称 0 0` 才能给红石"已结束"信号。

### 4.3 暂停 / 继续 / 删除

```
/countdown_stop 名称        # 暂停（画面冻结在当前时间）
/countdown_continue 名称    # 继续
/countdown_remove 名称      # 删除
```

首个参数按 Tab 会补全已有倒计时名称。

### 4.4 `/countdown_test` 红石联动

```
/countdown_test <名称> <min> <max>
```

剩余秒数落在 `[min, max]` 内 → 指令成功，命令方块的**成功次数 = 1**，旁边放红石比较器即可输出信号；不在区间 → 抛异常，比较器无信号。`min > max` 会自动交换。

```
/countdown_test wave1 0 0      # 倒计时已结束 → 有信号
/countdown_test wave1 1 10     # 最后 10 秒 → 有信号
/countdown_test wave1 0 999999 # 只要存在 → 恒有信号
```

> **口径差异**：`/countdown_test` 读的是服务端整秒剩余（向下取整），而屏幕上样式 4/5/6 显示的是向上取整的十分位。两者在同一瞬间可能差 1 秒。做精确判定请**以检测值为准**，或把区间放宽一格。

### 4.5 典型连招

```
# 30 秒后引爆：最后 5 秒开始抖屏，归零瞬间白屏 + 字幕
/countdown_add 6 bomb 30 255 90 60
# 命令方块 A（循环，接比较器）：/countdown_test bomb 0 5  → 接 /shake @a 20 10
# 命令方块 B（循环，接比较器）：/countdown_test bomb 0 0  → 接 /white @a 35 1.0 与 /sub @a 80 撤离失败
```

## 5. 物品

### 5.1 三种线圈

共同点：

- **手持生效**：主手**或**副手拿着即可，不需要右键使用；
- **不用药水效果实现**：全部直接改物理量 / 生命值，所以没有粒子、没有 HUD 图标，画面干净；
- **可以和药水叠加**：因为不占用效果栏；
- 堆叠上限都是 1，只对玩家生效。

| 物品 | ID | 颜色 | 效果 |
|---|---|---|---|
| 加速线圈 Speed Coil | `jiezhimod:speed_coil` | 红 | 移动速度 **×5** |
| 重力线圈 Gravity Coil | `jiezhimod:gravity_coil` | 蓝 | 跳得更高，约 **6 格** |
| 治愈线圈 Healing Coil | `jiezhimod:healing_coil` | 绿 | 每秒回复 **4 点生命**（2 颗心） |

```
/give <玩家> jiezhimod:speed_coil
/give <玩家> jiezhimod:gravity_coil
/give <玩家> jiezhimod:healing_coil
```

**加速线圈**：拿起（从未持有变成持有）的那一瞬间会播放一次提示音，由服务端广播，所以旁边的人也能听到。实现上给玩家的 `MOVEMENT_SPEED` 属性挂一个 `MULTIPLY_TOTAL` ×5 修饰符，可与迅捷药水叠加（迅捷 I 时约 ×5.4）；属性由服务端权威同步，不会出现"拉扯 / 回弹"。

**重力线圈**：把跳跃初速度从原版的 `0.42` 换成 `1.0075`。按 MC 的离散物理算出来峰值正好是 **6.00 格**（同一套算法代入原版 `0.42` 得 `1.2522` 格，与公认的原版跳跃高度一致，可作校准基准）。和跳跃提升药水叠加时，先取出"原版已经加上的额外量"再换成线圈初速度，所以线圈 + 跳跃提升 I ≈ 7.2 格。在水里 / 游泳时原版不走这套跳跃逻辑，因此水中不触发。

**治愈线圈**：服务端每秒（20 tick）调用一次 `heal(4.0F)`，即 **4 点生命 / 秒（2 颗心）**。与再生药水叠加时各加各的（再生 II 时合计约 6 点 / 秒）。想改成 4 颗心（8 点 / 秒），把 `HealingCoilEffect.HEAL_PER_SECOND` 改为 `8.0F` 重新构建。

### 5.2 喷气背包 + 喷气开关

| 物品 | ID | 位置 |
|---|---|---|
| 喷气背包 | `jiezhimod:jetpack` | 穿在**胸甲槽** |
| 喷气开关 | `jiezhimod:jet_switch` | 拿在**手上** |

**操作**：手持喷气开关，**按住右键**起飞，**松开右键**立刻失去动力。跳跃键爬升、WASD 推进。

**热量系统**：准星下方有一条热量条，**绿 → 黄 → 橙** 代表燃料消耗，满了会**过热**。过热后进入锁定状态，必须松开右键降温，等热量降到 30% 以下才能再次起飞。单次满燃料最多连续飞行 **18 秒**。

### 5.3 DFC 遥控器

`jiezhimod:dfc_remote` —— 用于绑定反应堆源与记录外部设备。详见第 7 章。

## 6. 方块：红石延时器

创造模式物品栏的「**jiezhimod-红石**」页里就这一个方块：**红石延时器** `jiezhimod:delay_block`。

### 6.1 它做什么

把红石信号**整体延后**一段时间再输出——上升沿和下降沿都延时，所以一段脉冲是"整段后移"，**不会被压扁也不会被吞掉**（1 tick 的短脉冲照样能穿过去）。

### 6.2 怎么用

1. **放下方块**（不挑方向，方块本身不用对准谁）；
2. **右键**方块打开设置界面；
3. 设置延时时间与输出方向，改完立即生效，不用拆了重放。

方块顶面画着一枚"时钟"，一眼就能认出这是延时装置。

### 6.3 设置界面

| 项目 | 说明 |
|---|---|
| 延时时间 | 直接填数值，旁边 `-` `-10` `+` `+10` 微调，数值最大 9999；换算后总时长封顶 1200000 tick（1000 分钟） |
| 单位 | `tick` / `秒` / `分` 三选一（20 tick = 1 秒，1200 tick = 1 分） |
| 输出方向 | `向前(直通)` / `向左` / `向右` / `三向`，**全部以信号进入的那一面为基准** |
| 实际延时 | 实时换算出的 tick 数与秒数 |
| 状态行 | 当前输入 / 输出电平，以及距离下一次翻转还剩多少 tick |
| 底部信息 | `输入来自: 南` / `输出: 北 / 东 / 西`，直接告诉你现在信号往哪走 |

### 6.4 输出方向怎么定（重点）

**输出方向跟着信号进来的那一面走，和方块摆放朝向无关。**

约定：`向前` = 信号**穿过去**继续沿同一个世界方向前进；`向左` / `向右` = 站在方块上顺着信号行进方向望过去的左手边 / 右手边。

| 信号从哪面进 | 向前（直通）出 | 向左出 | 向右出 |
|---|---|---|---|
| 北面 | 南面 | 东面 | 西面 |
| 南面 | 北面 | 西面 | 东面 |
| 东面 | 西面 | 南面 | 北面 |
| 西面 | 东面 | 北面 | 南面 |
| 上面 | 下面 | 下面（退化） | 下面（退化） |
| 下面 | 上面 | 上面（退化） | 上面（退化） |

- **向前（直通）**：只从对面输出，等于"电线上的延时器"；
- **向左 / 向右**：只从拐 90° 的那一面输出，等于"延时 + 转向"；
- **三向**：对面 + 左 + 右同时输出（**不含输入面**，所以自己的输出不会绕回来喂给自己）。

信号从**上面 / 下面**进来时没有"左右"可言（竖直方向绕 Y 轴旋转无定义），此时左 / 右 / 三向统一退化成正对面输出，不会报错也不会没反应。

输入方向在信号**上升沿**时锁存（同中继器），一个脉冲期间输出面保持不变；如果同时有多面送电，取**功率最大**的那一面作为来源。挪动线路后可以点界面上的"**重检方向**"。

方块同时提供弱信号与强信号，隔着实心方块也能把信号送过去。

### 6.5 典型用法

- **长周期时钟**：延时器 + 红石火把，最长换算到 1000 分钟（约 16.7 小时），比串联一堆中继器省事得多；
- **时序编排**：把「抖屏 / 白屏 / 字幕」挂在不同延时的支路上，一键演出；
- **收尾触发**：`/countdown_test` 出信号后接延时器，做"结束后 N 秒再放特效"。

## 7. DFC 监控显示器

完整说明见 **[DFC 显示器专题](DFC显示器.md)**。这里只放速查。

### 7.1 三块屏

| 方块 | ID | 页面 |
|---|---|---|
| DFC 监控显示器 | `jiezhimod:dfc_screen` | 核心页（温度 / 稳定度 / 能量 / 崩溃圆盘 / 运行时长 / 事件日志） |
| DFC 部件监视器 | `jiezhimod:dfc_monitor` | 部件页（同类部件合并统计） |
| DFC 自定义显示屏 | `jiezhimod:dfc_custom` | 自定义页（最多 8 条自选设备读数） |

**4 宽 × 3 高** 吊装多方块，放任意一格自动铺满 12 格，**下倾角由你放置瞬间的视线俯仰决定**——对着天花板下表面放置就会垂挂在头顶。

### 7.2 绑定反应堆源

拿 **DFC 遥控器** 右键 **DFC 核心**或 **DFC 稳定器** → 记录坐标；再右键显示器 → 完成绑定。**蹲下右键空气** 清空记录。

### 7.3 自定义屏接设备

1. 拿 DFC 遥控器，**蹲下右键**一台设备（储罐 / 电池 / 涡轮部件）→ 记录；
2. **蹲下右键**自定义显示屏 → 一次性接入全部记录；
3. **蹲下右键空气** → 清空全部记录。

最多 8 条。设备被拆后该条显示「离线」。

### 7.4 全局显示规则

| 规则 | 说明 |
|---|---|
| 刷新率 **0.05 秒** | 恰好 1 tick，数据与画面同一个节拍 |
| 所有数值 **2 位小数** | 温度 / 能量 / 液量 / 百分比 / 变化率；时间类保持整数秒 |
| 运行时长**温度归零清零** | 一停堆就重新计时 |
| **未到 100°C = 离线** | 整屏改画「离线」页 |
| **0 度 + 0 稳定度不显示危急** | 冷堆的 0% 是"没开机" |
| **重新加载存档会重启所有屏幕** | 重进存档 / 换维度 / 重载区块后重走开机流程 |
| **核心开始炸时整屏报错 301** | 坍缩度离开 0 即触发，4 秒后自动重启屏幕 |

## 8. 聊天栏与通知

### 8.1 聊天栏动效

模组会接管整条聊天栏（`GuiNewChat`）的绘制，所有消息（玩家聊天、系统提示、指令回显）统一走三套动画：

| 时机 | 效果 |
|---|---|
| 消息到达 | 从底部往上**弹起**（带一点点回弹）+ 淡入 |
| 存活 10 秒后 | 向**左滑出**并淡出（只改透明度，不从历史里删掉） |
| 按 `T` / `/` 打开聊天 | 可见的历史消息**从左侧滑入**（逐行错开） |

其它规则：

- 堆叠顺序：**先发送的消息在上方**，新的消息往下堆（原版 MC 的顺序）；
- 打开聊天期间时间照常走，但保持期失效，历史消息恒清晰、不会淡出；
- 聊天透明度、字号、`chatWidth`/`chatHeight` 等原版设置依然生效；
- 鼠标悬浮 / 点击链接、复制、`↑` 取回历史输入、滚轮翻阅等行为保持原版一致。

### 8.2 `/notice` 右下角通知

```
/notice <标题> <正文...>
```

- 第一个参数是**标题**，其余全部拼成**正文**（正文里可以直接写空格，不需要引号）；
- 立即推送给**所有在线玩家**；
- 支持颜色码：打不出分节号就写字面的 `\u00a7`（与 `/sub` 一致）；
- 回显：`Notice sent to N player(s): <标题>`。

```
/notice 副本开始 第一阶段：\u00a7a守住中央大厅
/notice \u00a7c警告 \u00a7e30 秒后场地崩塌
```

### 8.3 通知的显示规则

| 项目 | 取值 |
|---|---|
| 位置 | 屏幕**右下角**（距边缘 8 px），向上堆叠 |
| 外观 | 圆角黑框（圆角半径 6）+ 极淡的白色描边；**标题在上、正文在下** |
| 停留 | **8 秒**，之后向右侧滑出并淡出 |
| 排列 | 先发送的在下方，最新的在上方 |
| 同屏上限 | 6 条（更早的仍进历史） |
| 历史 | 保留最近 **300** 条 |

### 8.4 `P` 键：通知历史全屏界面

按 **`P`** 打开全屏界面：

- 显示全部历史通知（最多 300 条），最新的在最上面；
- **滚轮**上下滑动，右侧有滚动条；
- **Esc** 退出；
- 每张卡片右上角显示收到通知的时间（`HH:mm:ss`）；
- 打开界面**不会暂停游戏**。

> **为什么用 `P`？**
> 之前默认绑 `N`，后来发现整合包里 `N` 已被别的 mod 占用；改成 `Ctrl/Shift + N` 之后，**组合键同样会被别的 mod 拦截**。所以最终方案是：换成一个游戏内几乎没人用的功能键，并且裸键触发。
>
> 唯一必须守住的底线是：**任何界面打开时都不触发**。1.12.2 里即使聊天界面开着，按键状态照样每 tick 累积，玩家在聊天框打出字母 p 时，通知界面会把聊天框顶掉，输入到一半的字和历史全丢。
>
> 快捷键可在 `Options → Controls` 的 `jiezhimod` 分类下自行改成任意键。

## 9. 目标选择器

第一个参数以 `@` 开头时按原版选择器解析，语法与 `/kill`、`/effect` 完全一致：

| 选择器 | 含义 |
|---|---|
| `@p` | 最近的玩家 |
| `@a` | 所有玩家 |
| `@r` | 随机玩家 |
| `@e` | 所有实体（配合 type 等参数） |
| `@s` | 执行者自己 |

高级参数：`@a[c=3]`（最近 3 名）、`@a[lm=5]`（等级 ≥5）、`@a[team=red]`（红队）、`@a[x=1,y=64,z=1,r=10]`（半径 10 格内）、`@a[score_kills_min=3]` 等。

**省略目标的规则**：

- 你是玩家 → 只作用于你自己；
- 你是控制台 / 命令方块 → 作用于所有在线玩家。

Tab 补全首参数会提示 `@p @a @r @e @s`。

## 10. 颜色码

1.12.2 的聊天框无法直接输入分节号 `§`，请写 **`\u00a7`**（模组会自动转成真正的分节号后交给 FontRenderer 渲染；能直接打出 `§` 也可以）。

| 代码 | 效果 | 代码 | 效果 |
|---|---|---|---|
| `\u00a70` | 黑 | `\u00a78` | 深灰 |
| `\u00a71` | 深蓝 | `\u00a79` | 蓝 |
| `\u00a72` | 深绿 | `\u00a7a` | 绿 |
| `\u00a73` | 深青 | `\u00a7b` | 青 |
| `\u00a74` | 深红 | `\u00a7c` | 红 |
| `\u00a75` | 紫 | `\u00a7d` | 粉 |
| `\u00a76` | 金 | `\u00a7e` | 黄 |
| `\u00a77` | 灰 | `\u00a7f` | 白 |
| `\u00a7l` | 粗体 | `\u00a7o` | 斜体 |
| `\u00a7n` | 下划线 | `\u00a7r` | 重置 |

```
/sub @a 100 \u00a7l\u00a7c【最终阶段】\u00a7r\n\u00a77守住核心 30 秒
```

## 11. 常见问题

见 **[常见问题](常见问题.md)**。摘几条最常遇到的：

- **特效没反应** → 指令权限是 2；客户端与服务端都要装。
- **DFC 屏幕显示 `NO LINK`** → 没装 HBM 核科技，或还没绑定数据源。
- **DFC 屏幕整屏「离线」** → 反应堆温度没到 100°C。
- **倒计时归零后 `00:00` 挂着** → 刻意保留，方便红石检测"已结束"。
- **启动崩溃 `integrity check failed`** → jar 被改动过，换官方发布版。
