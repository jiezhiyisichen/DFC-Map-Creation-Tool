# 构建指南 · 从源码到可用的 jar

> 作者：树上的节枝（jiezhi） · B站：<https://space.bilibili.com/3494363348863838>

本文说明如何从源码构建出**能进游戏的** jar，以及为什么这个项目不能"只跑一次 `gradlew build`"。

---

## 1. 环境要求

| 依赖 | 要求 | 说明 |
|---|---|---|
| **JDK** | **9 及以上**（推荐 21） | 编译目标是 Java 8 字节码，但构建脚本用到 `javac --release 8`，JDK 8 不支持 |
| **Gradle** | 用仓库自带的 `gradlew` | 无需单独安装 |
| **Forge** | `1.12.2-14.23.5.2864` | 由 `build.gradle` 声明，首次构建会自动下载 |
| **ProGuard** | **7.4.2** | **需要自行下载**并放到 `tools/proguard-7.4.2/` |
| **Python** | 3.8+ | 运行 `tools/` 下的构建脚本 |

### 下载 ProGuard

从 <https://github.com/Guardsquare/proguard/releases/tag/v7.4.2> 下载 `proguard-7.4.2.zip`，解压后使目录结构为：

```
tools/proguard-7.4.2/lib/proguard.jar
```

> 这个 35 MB 的第三方工具**不入库**（已在 `.gitignore` 中排除），避免仓库臃肿。

### 关于路径

仓库内的构建脚本**不含任何机器专属的绝对路径**：

- `tools/proguard.pro` 用相对路径 + `<user.home>` 占位（ProGuard 的相对路径**相对配置文件所在目录**解析）；
- `tools/seal_inject.py` 的项目根由脚本自身位置推导，JDK 自动探测，依赖 jar 从 `~/.gradle` 缓存按文件名搜索；
- `tools/selftest/run_selftest.py`、`tools/canvastest/run_dump.bat` 同理。

**首次构建前先跑一次 `gradlew build`**，让 Gradle 把 Forge / netty / log4j / ASM 等依赖下载到本地缓存——后面的脚本都靠缓存里的这些 jar。

## 2. 构建三步（缺一不可）

```bat
:: 1) 编译
gradlew.bat build --offline
::    -> build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar

:: 2) 混淆
java -jar tools\proguard-7.4.2\lib\proguard.jar @tools\proguard.pro
::    -> tools\obf.jar

:: 3) 补帧 + 注入完整性封印
python tools\seal_inject.py tools\obf.jar build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar
::    -> 覆盖写回 build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar（这才是最终产物）
```

> `seal_inject.py` 的两个参数都可以省略：默认输入 `tools/obf.jar`，默认输出 `build/libs` 下的主产物。

### 为什么必须三步全跑

这个 jar **内置双重完整性校验**（防篡改）：

1. 构建期，`seal_inject.py` 把**全部业务类的聚合哈希 `H_rest`** 写进 `SealA`；
2. 再算 `SealA` 自己的哈希 `H_A`，把 `H_rest + H_A` 写进 `SealB`；
3. 运行时 `SealA.verify()` 校验 `H_rest` 与 `SealB` 是否存在，`SealB.verify()` 校验 `H_rest` 与 `SealA` 的内容。

所以：

- **改了任何 Java 源码**却不重跑三步 → `H_rest` 变了，进游戏直接 `integrity check failed` 崩溃；
- **纯资源改动也一样要重跑**（贴图 / `mcmod.info` / 语言文件都会进 jar，同样参与哈希）。三步是幂等的，多跑不会出问题；
- 第 2 步的 ProGuard **不能加 `-dontpreverify`**：Gradle 的 `reobfJar` 会丢掉 `StackMapTable`，而 JVM8 对 class 版本 52 且含分支的方法**强制要求** StackMapTable，缺了就 `VerifyError`。补帧工作由第 3 步里的 `FixStackMap`（ASM `COMPUTE_FRAMES`）完成。

## 3. 构建后必验

```bat
:: ① 全类 StackMapTable 完整性（期望输出 OK）
python tools\check_stackmap.py build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar

:: ② 离线断言测试（期望 ALL DONE / ALL GREEN，当前基线 637 条）
python tools\selftest\run_selftest.py

:: ③ 封印自检（期望 SEAL OK）
javac -nowarn -cp "build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar" -d tools\testmain\out tools\testmain\TestMain.java
java -cp "tools\testmain\out;build\libs\jiezhi-1.12.2-dfcmaptools-3.4.jar" TestMain
```

`run_selftest.py` 除了跑断言，还会做几件静态检查（这些坑在游戏里都是**静默失败**，只能靠构建期拦住）：

| 检查 | 拦的是什么坑 |
|---|---|
| `mcmod.info` 必须是严格 JSON | 描述里一个未转义的引号就让整个 `mcmod.info` 解析失败 |
| 每个方块实体类都已 `registerTileEntity` | 漏注册 → 区块保存时抛 `missing a mapping!`，重载后方块实体连同数据一起丢 |
| 终态 jar 内无明文敏感串 | 兜底防止关键字符串泄漏 |
| 模型 / blockstates / 贴图引用完整性 | 一处对不上就是游戏里的"透明方块"或紫黑缺模型，日志只有一行 warning |
| 语言键齐全 | 缺键时游戏直接把 key 名显示给玩家（如 `key.jiezhimod.notice`） |
| 版权式代码哨兵 | 例如 `drawDial` 里不许再出现潜在增益的字样、必须仍然画稳定度与崩溃百分比 |

## 4. 开发辅助工具

| 工具 | 命令 | 用途 |
|---|---|---|
| **离屏渲染预览** | `cmd /c tools\canvastest\run_dump.bat` | **不进游戏**，把三块屏的任意页面渲染成 PNG（README 配图就是这么来的）。改了画布代码后先删 `tools/canvastest/out` 再跑 |
| **离线自测** | `python tools\selftest\run_selftest.py` | 见上 |
| **封印自检** | `tools\testmain\TestMain.java` | 见上 |
| **篡改测试** | `python tools\tamper.py <mode>` | 生成各种被篡改的 jar（翻转业务类字节 / 删掉 SealA / 删掉 SealB…），用来验证 Seal 真的会拦下来 |
| **配图生成** | `python tools\gen_readme_assets.py` | 生成 `screenshots/` 下的横幅、物品一览、方块一览（需要 Pillow） |
| **贴图生成** | `python tools\gen_block_textures.py`、`gen_dfc_assets.py`、`gen_jetpack_textures.py` | 程序化生成方块 / DFC / 喷气背包的贴图资源 |

## 5. 部署到游戏

把**最终产物**（跑了三步之后的那个 jar）放进：

```
.minecraft/mods/
```

服务端同样要放一份（特效靠网络包下发）。

> 注意：**不要**把 `tools/obf.jar` 直接丢进游戏——那只是中间产物，没有注入封印，或者封印与内容不匹配，会直接崩溃。

## 7. 常见构建问题

**Q：`integrity check failed` / 进游戏直接崩？**
三步没跑全，或者跑完又改了源码 / 资源。重跑三步即可（幂等）。

**Q：`VerifyError: Expecting a stackmap frame at branch target`？**
第 3 步（补帧）没跑，或 ProGuard 配置里被加了 `-dontpreverify`。

**Q：`seal_inject.py` 报"找不到 ASM / Forge / netty…"？**
先跑一次 `gradlew build --offline`（或去掉 `--offline`）让 Gradle 把依赖下载到 `~/.gradle/caches`。

**Q：`javac: invalid flag: --release`？**
用到了 JDK 8。换 JDK 9+，或设置 `JAVA_HOME`。

**Q：ProGuard 报一堆 unresolved references？**
正常。配置里有 `-ignorewarnings`，且 library jars 故意只放了必要的那几个（Forge universal jar 不含 `net.minecraft.*`，ProGuard 解析不到继承关系，所以相关包都写了显式 `-keep`）。
